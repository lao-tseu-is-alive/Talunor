Talunor is a small AI agent that runs in your terminal, on your machine. Its memory is one local database file. It is built small on purpose: it exists as a course, so you can read all of it and check the guarantees yourself.

This video traces one turn through the loop — and stops twice at places where a wall turned out to have a door:

• An approval that bound the tool's NAME but not its ARGUMENTS. You could approve "list my files" and something else could arrive at execution. Nothing crashed; it was found by reading the code.

• A refusal that vanished. When a new claim contradicted a stored fact and lost, the system threw the claim away — correctly refusing, and silently forgetting anyone had asked. For four releases that looked exactly like a system working.

Both are fixed, and both are written up in public, because a guardrail nobody has attacked is a guess.

—

WHAT IT IS NOT (the part most project videos skip)

• Not a production framework. One worked example, built to be read. Don't depend on it.
• The strong sandbox is the container one. The simpler Linux-namespaces backend has NO seccomp filter — a speed bump, not a boundary. Don't run hostile code behind it, and note it's the one you silently get if no container runtime answers.
• Fencing untrusted text is a mitigation, not a wall. The model still reads it.
• "A tool observed it" is a promise no built-in tool makes yet — today, facts learned from tool output are marked as inference.
• A belief can be contested, never vindicated. Nothing clears the flag.
